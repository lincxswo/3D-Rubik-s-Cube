# 项目文档 · 目录

这里是 3D 魔方项目的全套文档。建议按下面的顺序读：

| 文档 | 讲什么 | 什么时候看 |
| --- | --- | --- |
| [architecture.md](./architecture.md) | 文件一层层的架构：分了哪几层、每个文件干什么、谁能引用谁 | 想搞清"代码是怎么组织起来的" |
| [domain-model.md](./domain-model.md) | 魔方的数据长什么样：54 格状态、坐标、转动记号、顺时针的定义、复原是怎么算的 | 想改魔方逻辑（转动 / 打乱 / 复原） |
| [testing.md](./testing.md) | 测试清单：每个测试文件守着哪条规矩、怎么跑 | 改完代码要跑测试 / 想知道"为什么这么测" |
| [development.md](./development.md) | 环境与工具：node、npm 在哪，三条命令，装了哪些依赖，已知的环境坑 | 换电脑、重装环境、遇到莫名其妙的报错 |

> **重要区分**：`development.md` 记的是**这台电脑的环境**（node 装在哪、缓存目录在哪、沙箱怎么授权）。
> 这些**不属于项目**——项目代码里一个字都没有引用它们。
> 项目代码只认 `src/` 里的东西，换台电脑照样能跑。这也是本文档把两者分开写的原因。

## 一分钟看懂这个项目

- 技术栈：Vite + TypeScript + Three.js（3D），测试用 Vitest。
- 代码分 **3 层 + 1 个接线员**：

| 层 | 目录 | 一句话职责 | 能不能用 three |
| --- | --- | --- | --- |
| 核心逻辑层 | `src/core/` | 魔方是什么样、怎么转、怎么打乱、怎么复原——全是纯数据计算 | **禁止**（有测试守着） |
| 渲染层 | `src/render/` | 把核心层的数据画成 3D 画面，负责动画和悬停高亮 | 唯一允许的地方 |
| 界面控件层 | `src/ui/` | 12 个转动按钮的生成和鼠标事件 | 不碰 |
| 接线层 | `src/main.ts` | 把上面三层连起来，管理"动画播放中不接受新指令"等时序 | 只做接线 |

- **一条铁律：逻辑与画面分离。** 画面只能"读"逻辑的数据，永远不能反过来改它。
  这条规矩不是靠自觉，而是有专门的测试盯着（`src/core/separation.test.ts`）：只要有人在 `src/core/` 里写了一句 `import ... from 'three'`，测试立刻变红。

## 项目做什么 / 不做什么

**做这些：**

- 3×3×3 魔方，26 个小方块（中间的看不见，去掉），标准配色（白上、黄下、绿前、蓝后、红右、橙左）。
- 12 个转动按钮：`U U' D D' L L' R R' F F' B B'`，每次转 90°，带约 200ms 动画。
- 打乱：输入 n（默认 20，限制 1~30），禁止连续两次转同一个面。
- 复原：倒推"你真实做过的每一步"，能【下一步】【上一步】单步走，并显示"第 3 / 20 步：R'"。
- 重置：一键变回初始的复原状态。
- 鼠标悬停在转动按钮上时，对应那一层 9 个小方块加亮黄色描边。
- 鼠标拖动转视角、滚轮缩放（**只改看的角度，不改魔方状态，也不改哪个面叫 U/F/R**）。

**刻意不做（别加）：**

- 不要计时器、不要排行榜、不要登录。
- 不要 2×2 魔方。
- 不要手机适配。
- 想加任何上面没提过的东西，先问。

## 文档维护约定

- 文档和代码放在一起（同一个 git 仓库），改代码时顺手改对应文档。
- 文档里**不要**写"某个文件有多少行"这类会过期的数字，也别抄代码原文——写下"为什么"和"规矩"。
- 环境相关的路径只写在 `development.md`，其它文档一律不写绝对路径。
