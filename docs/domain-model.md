# 核心模型与约定

这份文档讲"魔方在代码里到底是怎么表示的"，以及那些**一旦搞反就很难发现**的约定。
改转动 / 打乱 / 复原逻辑之前，先看这里。

> 本文件里的规则全部由 `src/core/` 里的代码实现，且都有测试盯着（见 [testing.md](./testing.md)）。

---

## 1. 魔方状态是怎么存的：54 格贴纸

不存"每个方块在哪、朝哪"，而是存**每个面上的 9 格颜色**：

```
魔方 = 6 个面
每个面 = 9 格（3×3）
一共 6 × 9 = 54 格，每格只有一个颜色
```

- 面：`U` 上、`D` 下、`F` 前、`B` 后、`R` 右、`L` 左（顺序固定为 `U D F B R L`）
- 颜色：`white` 白、`yellow` 黄、`red` 红、`orange` 橙、`blue` 蓝、`green` 绿
- 每格编号 0~8：**站在这个面外面正对着它看**，从左上到右下

```
0 1 2      0 = 左上     4 = 正中间     8 = 右下
3 4 5
6 7 8
```

小方块的"位置和朝向"由另一份几何数据算出来（`cubies.ts`），不需要存在状态里。
这样存的好处：**转动只是把颜色在 54 个格子里搬家**，非常简单，也特别好测。

## 2. 标准配色

复原状态下每个面的颜色：

| 面 | 位置 | 颜色 |
| --- | --- | --- |
| `U` | 上 | 白 |
| `D` | 下 | 黄 |
| `F` | 前（相机初始正对的那面） | 绿 |
| `B` | 后 | 蓝 |
| `R` | 右 | 红 |
| `L` | 左 | 橙 |

对色关系：**白对黄、红对橙、蓝对绿**。

判定"已复原"的规则很简单：**每个面的 9 格都是同一种颜色**（不关心整体被怎么摆放）。

## 3. 26 个小方块：坐标与朝向

3×3×3 一共 27 个位置。用三个数字表示位置，每个数字只能是 **-1、0、1**：

- `x`：-1 最左、0 中间、1 最右
- `y`：-1 最下、0 中间、1 最上
- `z`：-1 最后、0 中间、1 最前

去掉正中间的 `(0,0,0)`（看不见），剩下 **26 个**——这就是"26 个小方块"的来历。

每个面的"朝外方向"是固定的：

| 面 | 朝外的方向 | 说明 |
| --- | --- | --- |
| `U` | `+y` | 上 |
| `D` | `-y` | 下 |
| `R` | `+x` | 右 |
| `L` | `-x` | 左 |
| `F` | `+z` | 前 |
| `B` | `-z` | 后 |

小方块分三种，它们露出几个面：

| 类型 | 个数 | 露出几个面 |
| --- | --- | --- |
| 角块（三个坐标都不是 0） | 8 | 3 |
| 棱块（有一个坐标是 0） | 12 | 2 |
| 面心块（有两个坐标是 0） | 6 | 1 |

合计露出的面：`8×3 + 12×2 + 6×1 = 54`，正好等于 54 格贴纸，一格不多一格不少。

## 4. 转动记号

| 记号 | 意思 |
| --- | --- |
| `U` `D` `L` `R` `F` `B` | 转对应那一面 90°，顺时针 |
| 后面加 `'`（例如 `R'`） | 同一面，逆时针 90° |

一共 12 种合法记号，顺序就是页面上按钮的顺序：
`U U' D D' L L' R R' F F' B B'`

### 4.1 "顺时针"到底怎么算（最容易搞反的地方）

定义：**站在那个面的外面，正对着它看时的顺时针。**

| 转哪面 | 怎么看 |
| --- | --- |
| `U` | 从上往下看是顺时针 |
| `D` | 从下往上看是顺时针 |
| `R` `L` `F` `B` | 从该面外侧看是顺时针 |

为了不靠"感觉"，代码里用的是这条数学规则：

> **顺时针转 = 绕该面的"朝外方向"旋转 -90°（右手定则）。**

写成公式就是 `v' = n(n·v) − n×v`（`n` 是该面朝外的方向）。这条公式**同时用来转数据、也用来转画面**，所以画面和数据不可能对不上。

### 4.2 一张"别搞反"的对照表（测试里就是这么验的）

顺时针转某个面之后，"前面"这个方向会指向哪里：

| 转哪面 | 前面 → 去哪 |
| --- | --- |
| `U` | 前面 → **左面** |
| `D` | 前面 → **右面** |
| `R` | 前面 → **上面** |
| `L` | 前面 → **下面** |
| `F` | （前后轴上的方向转不动，改用"上面"做参照）上面 → **右面** |
| `B` | 上面 → **左面** |

> 一个必须记住的推论：**转某一面时，那一面自己的 9 格也在转**。
> 因为复原状态下每个面都是纯色，这 9 格转不转肉眼看不出来——所以测试是先转一次 `R`
> 把绿色弄到上面，再转 `U`，确认那格绿色从"上右"跑到了"上前"。

## 5. 一步转动是怎么算出来的

数据上的做法（`turns.ts`）：

1. 把 6 个面的 54 格颜色**抄一份**（没被动到的格子就保持原样）。
2. 找出"这一层"的 9 个小方块（判断方法：它在这个面朝外方向上的坐标正好是 ±1）。
3. 对每个小方块，把**它的位置**和**它每个朝外方向**一起绕这根轴转 90°。
4. 颜色跟着搬过去：原来在"某个方块、某个朝向"上的颜色，搬到"转过去之后的位置、转过去之后的朝向"上。

两个重要性质：

- **不修改传进来的旧状态，而是返回一个新状态。** 因为动画播放的那 200ms 里，画面显示的是旧状态，
  数据要等动画演完才提交——新旧两个状态必须同时存在。
- 逆时针 90° 不用另写一套算法，**顺时针转 3 次**就是逆时针。

## 6. 打乱规则

- 用户输入 `n`，默认 **20**，限制在 **1~30**（小于 1 当 1，大于 30 当 30，填了非数字用默认值）。
- 随机生成 n 步，**禁止连续两次转同一个面**。
  实现方式是"每一步都从'和上一面不同'的候选里挑"，所以天然不可能违反，而不是"生成完再检查"。
- 这次的打乱步骤会**单独存一份**（以后要显示"打乱序列"时用得上）。

## 7. 复原：靠"操作记录"倒推，不是靠打乱步骤

### 7.1 操作记录（history）

**从上次复原（或重置）以来，你真正做过的每一步**，按顺序记下来。包括：

- 打乱的每一步；
- 你手动点的每一次转动；
- 别人绕过界面强行转动的也算。

如果某一步刚好把魔方弄回了复原状态，这份记录会**自动清空**——记录的意义只是"离复原还差哪些步"。

### 7.2 不倒式（不变式）

> **把操作记录里的步骤，从"复原状态"依次走一遍，必然等于当前的状态。**

这条是整套复原功能的地基。测试里几乎每个操作之后都会验它（还有一条 400 次随机乱操作的压力测试专门盯着）。

### 7.3 倒推计划

```
复原计划 = 操作记录 倒着排 + 每一步都反过来
例：记录是  U  R'        计划就是  R  U'
走完计划 = 每一步都被抵消 = 回到复原
```

- 点【一键复原】**只把计划装填好、进入复原模式，不替你走路**（魔方一动不动）。
- 点【下一步】：把记录里的**最后一步"还掉"**（反着转一次），并从记录里删掉它，进度 +1。
- 点【上一步】：把刚还掉的那一步**再转回去**，并重新记回操作记录，进度 −1。
- 记录被还空 = 魔方复原 = 记录自动清空。

> **为什么不用"只记打乱步骤"？**
> 因为那样计划只能抵消打乱，前提是"打乱之前魔方必须是复原的"。
> 一旦手动转过，前提就没了，那时无论重新打乱多少次都回不到复原——是个死循环。
> 记"真实做过的每一步"之后，倒推永远有效。

### 7.4 复原模式（restoring）的规矩

| 规矩 | 说明 |
| --- | --- |
| 12 个转动按钮置灰 | 不接收手动转动指令 |
| 提供【退出复原模式】 | 退出后进度保留，再点【一键复原】可以接着走 |
| 绕过界面强行转动 | **立刻暂停**正在播的动画 → 执行用户这一步 → **剩下的计划全部作废** → 提示"计划已失效，请重新点一键复原" → 退出复原模式、按钮恢复 |
| 再次点【一键复原】 | 会按**新的**操作记录（含刚才那一下）算出一份新计划，照样能一路复原 |

### 7.5 重置

一键回到初始复原状态：状态变成复原、操作记录清空、计划清空、模式回自由、提示"已重置到初始的复原状态"。**不做动画，直接到位。**

## 8. 会话（Session）长什么样

一个"会话"就是一份纯数据，界面只是把它画出来：

| 字段 | 含义 |
| --- | --- |
| `state` | 魔方现在的状态（54 格颜色） |
| `history` | 从上次复原以来的全部操作（复原就是把它一步步还掉） |
| `scramble` | 最近一次打乱的步骤（单独留档） |
| `plan` | 本次复原计划（进复原模式时按 history 算的快照） |
| `cursor` | 复原计划已经走了几步 |
| `phase` | `idle` 自由模式 / `restoring` 复原模式 |
| `notice` | 要显示给用户的提示，没有就是 `null` |

**进度文字**格式：`第 3 / 20 步：R'`
含义是"**已经走完 3 步，刚刚走的那一步是 R'**"。一步都没走时显示"第 0 / 20 步：还没开始"。

## 9. 悬停高亮（画面规则，不影响上面任何数据）

- 鼠标移到某个转动按钮上 → 高亮它字母对应的那一面（`R` 和 `R'` 都是右面）。
- 高亮的是**那一层的 9 个小方块**（不只是那一面正对着的 9 格贴纸，还包括这 9 个方块侧面露出的贴纸），
  所以你能一眼看出"点这个按钮会转哪一层"。
- 表现：被指到的那一层**发光 + 亮黄色粗描边**，其余的面**轻微压暗**。
  之所以不只调亮目标：**白色的面已经在亮度天花板上了**，再加光还是白，看不出变化。
- 鼠标移开立刻恢复，切换按钮也不留残影——因为高亮是"按当前指着的面整体重算"的纯函数，不存在"残留"这种东西。
